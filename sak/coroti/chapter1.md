    스레드 생성비용이 비싼 이유:


메모리 할당: 각 스레드는 자체적인 스택 메모리가 필요합니다. 기본적으로 스레드 스택은 1MB 정도의 메모리를 차지하며, 이 메모리를 할당하고 초기화하는 과정이 필요합니다.
커널 리소스: 운영체제는 각 스레드에 대해 커널 수준의 자료구조를 생성해야 합니다. 스레드 제어 블록(TCB)을 만들고, 스케줄링 큐에 추가하며, 스레드 ID를 할당하는 등의 작업이 필요합니다.
초기화 작업: 스레드의 컨텍스트(레지스터 값, 프로그램 카운터 등)를 초기화하고, 스레드 로컬 스토리지(TLS)를 설정해야 합니다.

작업전환(Context Switching)비용이 비싼 이유:
하드웨어 상태 저장: 현재 실행 중인 스레드의 CPU 레지스터 값, 프로그램 카운터, 스택 포인터 등을 메모리에 저장해야 합니다.
캐시 오염: 작업전환 시 CPU 캐시가 이전 스레드의 데이터로 채워져 있어, 새로운 스레드는 자신의 데이터를 다시 캐시로 로드해야 합니다. 이는 캐시 미스를 증가시키고 성능 저하를 일으킵니다.
TLB 플러시: 프로세스 간 전환 시에는 Translation Lookaside Buffer(TLB)를 비우고 새로운 프로세스의 페이지 테이블 엔트리로 다시 채워야 합니다.
스케줄러 오버헤드: 운영체제는 다음에 실행할 스레드를 선택하고, 스케줄링 큐를 업데이트하는 등의 작업을 수행해야 합니다.

## 코틀린이란 무엇이며, 왜 필요한가
#### 코틀린 정적 타입 지정언어
- 모든 타입을 컴파일 시점에 검증
- 타입 추론 지원
- 장점
  - 메소드 호출 빠름
  - 신뢰성 - 컴파일러가 정확성 검증
  - 유지 보수성
  - 도구 지원

### 함수형 프로그래밍
- 일급 시민 함수: 함수를 저장 및 인자로 다른 함수에 전달 가능
  - 함수를 일반 값처럼 사용 가능
    - 람다식 코드 간결, 지연 연산, 익명 함수
    - 고차 함수는 함수를 매개변수로 사용하거나 함수를 반환하는 함수. 이와 같은 조건에 부합하기 위해 1급 객체
- 불변성: 내부 상태를 불변 객체를 사용
- 부수 효과 없음: 입력에는 항상 같은 출력 (순수함수)
- 장점
  - 간결성
  - 함수를 값처럼 사용하며 강력한 추상화 => 중복 코드 방지
  - 다중 스레드 환경에서 안전, 같은 데이터를 여러 스레드에서 변경 불가
- 코틀린의 함수형 프로그래밍 지원환경
  - 데이터 클래스로 불변 값 객체
  - 람다 식
  - 함수 타입 지원
  - 컬렉션

### 코틀린의 철학
- 실용성
- 간결성 - 람다,게/세터 지원등
- 안정성 - JVM, 컴파일, nullable
- 상호 운용성
